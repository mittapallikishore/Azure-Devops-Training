# Git Workflow and Collaboration

## Objective
Practise using Git branches, commits, and pull requests to manage changes safely.

## 1. Repository
A repository stores project files and their version history.

## 2. Branch
A branch allows changes to be developed separately from the main branch.

**Example branch:** `feature/day-02-git-workflow`

## 3. Commit
A commit records a snapshot of changes with a message explaining the work.

**Example command:**
```bash
git commit -m "Add Git workflow documentation"
```

## 4. Pull Request
A pull request proposes merging a feature branch into the main branch so the changes can be reviewed before merging.

## 5. Code Review
A reviewer checks the proposed changes for correctness, clarity, security, and maintainability.

## 6. Merge Conflict
A merge conflict occurs when Git cannot automatically combine competing changes. Review the affected file, resolve the conflict, and test the result before committing.

## Practical Activity
- Created a feature branch.
- Documented the purpose of repositories, branches, commits, pull requests, reviews, and merge conflicts.
- Next: commit the documentation, push the branch, and practise a pull request.

## Outcome
Documented a basic Git collaboration workflow using a feature branch.
