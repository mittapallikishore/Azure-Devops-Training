# Day 4 — CI Pipeline

**Date:** 15 October 2026

## Objective
Create a basic Continuous Integration (CI) pipeline in Azure DevOps to validate application changes automatically.

## Tasks Performed
1. **Azure DevOps Project:** Explored the project and configured the repository connection.
2. **YAML Pipeline:** Created a pipeline configuration using a YAML file.
3. **Dependency Installation:** Configured the pipeline to install the application's required dependencies.
4. **Build and Validation:** Added steps to check whether the application builds successfully.
5. **Automated Tests:** Configured available tests or validation checks to detect errors.
6. **Pipeline Triggers:** Learned how repository changes can automatically start pipeline runs.
7. **Pipeline Logs:** Reviewed execution logs to identify successful steps and troubleshoot failures.

## Observations
- YAML defines pipeline stages and tasks as code.
- Automated validation helps detect problems early.
- Pipeline logs make it easier to identify failed steps.
- Repository triggers help run validation when relevant changes are pushed.

## Outcome
Established a basic CI pipeline workflow for installing dependencies, validating application changes, running available tests, and reviewing results.
